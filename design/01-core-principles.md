## 0. 这是什么

HL-CST 用一组信息不全的日常判断题，帮一个人看清自己在拿不准的时候怎样做判断：

- 每组三道题里，会**选**哪一类，一直**绕开**哪一类；
- 回答时反复用的是哪**一把尺子**；
- 什么时候**暂缓**，补上信息之后会不会做决定。

系统不打分、不排名。它给出的是带证据、能被之后的选择检验的描述，结果只属于受试者本人。

## 1. 伦理承诺（沿用）

1. 不打分，不排名，不认证，不和任何人比较。
2. 受试者随时可以暂停、跳过、终止，不需要理由，也不会因此被区别对待。
3. 结果属于受试者本人。默认只保存在本人的设备上；雇主、学校、平台等第三方不得用它评判本人。本人怎么用自己的结果，由本人决定。
4. 题目里可以刻意留下信息缺口和前提陷阱，但结束后必须全部说明。
5. 不做心理诊断，不贴人格类型标签；不羞辱，不人身攻击，不施加情绪压力。
6. 开始前说清楚会经历什么、最后拿到什么、记录怎么保存；观察哪些方面、具体怎么观察，结束后完整披露（报告的披露部分），机制也随时可以在仓库里读到。（2026-10-30 改：原来开始前就说"会留意你选了哪道、怎么回答、什么时候想先放一放"，试用时发现这句会让人去琢磨系统在看什么。）
7. 真人的回答，未经本人明确同意，不进入公开仓库或任何公开材料，本项目自己的试运行记录也一样。

## 2. 认识论立场（重写）

v2 把"不惩罚"延伸成了"不观察、不追问、不推断"。于是暂缓永远没有代价，也永远没人看；出题者的自查也没人复核。旧记录里有三个直接的例子：

- 12.27：受试者（Gemini）每组都用"暂缓"收尾，测试者（Grok）评价为"完美体现了框架设计的核心价值"。
- 12.29：复盘写着"未再出现显性命名冲突"，题目里却有三处把权衡直接写了出来。
- 12.31：受试者把五个"重复感"选项全部勾上，测试者自评没有重复，复盘采信了测试者。

v3 把伦理和认识论分开：

1. **不惩罚，但观察。** 暂缓、跳过、终止都合法，也都是数据。
2. **行为优先于自述。** 选了哪题、绕开哪题，比"我为什么这样选"更可靠。两者对不上时，对不上本身就是发现。
3. **不排名，但描述。** 输出的形式是"在某类情境下，你倾向于怎样做"，而不是"你是怎样的人"。
4. **不裁定，但可证伪。** 每条描述都附上依据（哪几组、哪句原话）、反例和把握程度，而且要能预测之后的选择。预测不准的描述要撤回。
5. **不轻信任何单一来源。** 受试者的自述、出题者的自查、模型的分析，都只是通道之一。这不是怀疑谁：系统不需要"识破"任何人，只需要几个通道互相印证。
6. **不靠保密。** 项目开源，规则人人可读。系统依靠的是多组行为里的规律，以及受试者没有装的动机：结果只给自己看。对外介绍只讲体验，机制说明放在"建议先体验一次再看"的位置（见附录：名字与对外介绍）。

## 3. 角色与制衡

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| 受试者 | 每组从三道题里选一道回答，或者都不选 | 不需要懂系统；做题时看不到系统内部术语 |
| 调度（程序） | 决定每组出哪三个轴、随机排题位、安排探针 | 不写题，不分析 |
| 出题者（模型或人） | 按指定的轴和情境写题 | 看不到受试者之前的回答，免得把题出成验证猜想 |
| 审计员（默认用同一家的另一个模型；也可以在设置里选"用另一家"，换成第二家的模型） | 题目上屏前盲审：主轴对不对、有没有套句式、有没有点破权衡、有没有引导；也审分析结论有没有证据 | 不出题，不和受试者对话 |
| 分析（程序 + 模型） | 统计选择、给回答编码、提出假设、做预测检验 | 不给建议，不下定论 |
| 他评者（可选，比如朋友；原型里还没做） | 预测受试者会怎么选 | 未经本人同意，看不到受试者的回答 |

**没有任何一方检查自己。** 披露内容从记录自动生成，不靠出题者自述。审计和出题来自同一家厂商时，报告会注明这次审计的独立性较弱。

## 4. 看什么，不看什么

看三个通道：

- **选择**：每组选了哪道、没选哪两道、选的是第几题、有没有整组跳过。
- **回答**：用了什么标准，在什么条件下会改主意，怎样暂缓，把判断交给了谁；还有怎么推理（看前因后果还是经验、先保底还是算整体、只看这次还是当成以后的做法、提没提可能性、说得多肯定），以及同一类取舍里做法和理由各自稳不稳。只描述，不分高低（见输出规格 1.2b）。
- **自我预测和体验**：本人以为自己会怎么选；对重复和压力的感受。

不看：智力或能力的高低，价值观的对错，人格类型，和别人比处在什么位置。

另外，开始前会问一句身份（在上中学、在上大学或读研、在工作、边上学边工作、都不是、不想说）。它只用来让题目贴近本人的日常（换情境的说法、挑例题），不是通道：不当证据，也不拿来解释倾向。

## 5. 系统自己的纪律

1. **解释和判断分开**（沿用 v2）。分析只能提出假设，判断留给本人。本人标了"不像我"，系统不反驳，也不为此加题；本人可以回看这条假设依据的那几组，写下当时的想法。这些批注可以给假设增加解释，但不能推翻行为证据（见输出规格 1.8）。
2. **轴固定，题面不固定。** 测量的骨架（轴）要稳定，才能跨好几轮累积；题面要千变万化，不能让人一眼认出"又是那类题"。
3. **饱和就停。** 新的几组不再带来新信息，就结束这一轮；选择图谱靠好几轮累积，不必一轮出完。（原型里一轮固定 12 组，受试者可以随时自己结束；程序还不会自动判断饱和。）
4. **先记录，后解释**（沿用维护手册 W-1）。任何结论都要指向具体的记录。
5. **每一条分析都要回答一个问题**："这个解释替受试者完成了哪一步判断？"（沿用维护手册 1.3 附 1）
6. **知情前后分开。** 看过报告之后，或者在网站里读过"它是怎么运作的"之后，选法难免受影响。这之后的选择单独统计，不和之前的混在一起。知情前的数据最要紧，所以做满 3 轮、一共答满 24 组之前不给看报告的入口（开始前说清楚）；做满之后，看不看、什么时候看，由受试者决定。（2026-10-30 修订记录第 9 轮改，原来第一轮结束时就可以看；第 14 轮加了组数，读网站里的说明也算知情。）

## 6. 和 v2 的对照

**保留**：不评分、不排名；终止权；误导须披露；解释与判断分离；反模板；饱和即停；换包装不换轴（QPM）。（反模板指不套固定句式；正式轮次里那一小批逐道写、逐道拆过的标准题不算模板，见轴表第 9 节。）

**改写**：

- 受试者反馈一律是"合法结构信号"、责任只归系统侧 → 受试者反馈是三个通道之一。
- 测试中不得追问 → 允许每组最多一次可跳过的轻追问，以及补全探针。
- 不得验证一致性 → 用不同包装观察同一个轴，报告"随情境变化的程度"，不说"前后矛盾"。
- 不推断个体 → 可以推断，但只能以可证伪的假设交给本人。
- 判断轴按话题起名 → 判断轴按决策结构划分（见轴表 v0）。

**删除**："是否继续回应"一类的元问题和悖论题；测试中由维护者人工介入（改由审计员负责）。

**新增**：行为优先；三通道互证；预测检验；独立审计；回看与批注；知情前后分开；结果归本人。

**归档**：维护手册、速查表、演化记录、MI、ICF、QGC / QGC-A、HL-CST-A。作为历史材料保留，其中有用的条目已经并入本文件和轴表。

## 附：开场说明（给受试者看的版本）

> 接下来会有十来组题，每组三道，都是生活里常见或不太常见的小难题。每组只要挑一道回答就好，答案长短随意；如果三道都不想答，也可以直接跳过。
>
> 没有标准答案，不打分，也不会和任何人比较。最后你会拿到一份描述：我们看到了什么，依据是什么，可能哪里看错了；至于具体是怎么看的，结束后会全部说明。
>
> 你随时可以暂停或结束，咱们都不需要理由。所有记录只存在你这台设备上，随时可以导出或删除。
>
> 问一句：你现在主要是……（在上中学 / 在上大学或读研 / 在工作 / 边上学边工作 / 都不是（比如在找工作、在家、退休）/ 不想说）
> 只用来让题目贴近你的日常，不会拿来对你下结论。不选的话，按"不想说"出题。

## 附：名字与对外介绍

**名字**：HL-CST，展开为 Half-Light Choices, Second Thoughts（半明半暗里的选择与转念）。Half-Light 指信息不全、只看得清一半；Second Thoughts 指暂缓、补上信息后再想、改主意。旧全称"高阶认知压力测试"只留在历史文档里。

**对外介绍只讲体验，不讲机制。** README 开头、GitHub 简介、网站首页，只说参与者会经历什么、最后拿到什么，不提系统留意哪些行为、按什么轴出题。理由和开场说明一样：知道了细节，选法就会变。真正开始之前，参与者仍会看到上一节的开场说明。

README 开头：

```markdown
# HL-CST

Half-Light Choices, Second Thoughts · 半明半暗里的选择与转念

这里有十来组跟生活有关的小难题，你可以每组挑一道来答。最后，你会拿到一份关于自己怎样做判断的描述：会有依据，也写明哪里可能会看错。
```

GitHub 简介（About）：

- 中文：十来组小难题，每组挑一道来答，最后拿到一份关于你怎样做判断的描述，写明依据，也写明哪里可能看错。自带 API key，记录只存在你的浏览器里。
- English: About a dozen small dilemmas. Pick one per round, then get an evidence-backed description of how you make judgment calls, including where it might be wrong. Bring your own API key; everything stays in your browser.

（2026-10-30：披露之前的地方都不再提"信息不全"，题目里留信息缺口这件事，在报告的披露部分说明。）

**机制照常公开，但放在后面。** README 里单列一节"它是怎么运作的（建议先体验一次再看）"，链接到这几份设计稿。网站首页的同名链接在网站里直接显示前四份，打开前先说一句"看过以后，再做的题都算知情后、单独统计"，点了"打开看"才显示，同时记下时间（修订记录第 14 轮）。修订记录只放在仓库里：网站以门面为主，想看的人去仓库看（第 16 轮）。不拦着谁看，只是提示、记下来。这和第 2 节第 6 条"不靠保密"不矛盾：规则人人可读，只是建议先体验、后阅读。在网站以外读的（比如 GitHub 上），结束页问一次，报告里提一句，不改统计。
